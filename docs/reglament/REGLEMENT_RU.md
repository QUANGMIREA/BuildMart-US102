# Регламент проекта BuildMart (версия 0.1, учебный пример)

- Продукт: демонстрационная информационная система интернет-магазина строительных материалов.
- ЖЦ документа-регламента: сбор требований -> подготовка разделов -> перекрёстная проверка -> слияние -> проверка согласованности -> выпуск документа.
- ЖЦ проекта: итерационно-инкрементальный, от инициации до сопровождения.
- Управление: Kanban, двухнедельный обзор потока задач, WIP-limit = 2 на разработчика.
- Инженерные практики: XP (модульные тесты, непрерывная интеграция, ревью, рефакторинг).
- Артефакты: см. ../artifacts/ARTIFACT_REGISTER_RU.md (A01-A15).
- Ветки: main, develop, feature/US-*, release/x.y.z, hotfix/x.y.z.
- Тесты: до merge в develop, перед выпуском релиза; smoke test после развёртывания.
- Номер выпуска: MAJOR.MINOR.PATCH, кандидат: x.y.z-rc.N.
- Стратегия ввода: Б — ввод в эксплуатацию новой системы, поэтапный pilot.
- BCP: при остановке веб-заказов заказы принимаются оператором по телефону с последующей сверкой и переносом без дублирования.

Важно: полномасштабная разработка магазина, промышленная эксплуатация, платёжная интеграция и согласование с реальным заказчиком в демонстрацию не входят.
