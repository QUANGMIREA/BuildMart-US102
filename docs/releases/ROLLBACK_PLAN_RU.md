# Rollback Plan (demo, не промышленная процедура)

1. PM/DevOps объявляет инцидент, прекращает pilot и сохраняет журнал.
2. Фиксируются текущий Build ID, миграции, резервные данные и время.
3. Если схема БД совместима с предыдущим контейнером, запускается одобренный образ прежней версии.
4. Если несовместима, нельзя механически откатывать SQL миграции или стирать базу; выполняется отдельный утверждённый план восстановления, сверка заказов и данных.
5. QA повторно проверяет /health, /products; PM документирует решение о восстановлении.
6. В demo данные SQLite запечены в образ и теряются при пересоздании контейнера: это НЕ модель реального сохранения заказов.
