# BCP: отказ сервиса заказов (краткая процедура)

1. Ответственный фиксирует инцидент и отключает приём онлайн-заказов, чтобы исключить потерю/дублирование.
2. Операторы принимают заказы по телефону/электронной почте, фиксируют временный уникальный номер, покупателя, товар, количество и время.
3. Оператор проверяет остатки и согласует доставку по резервному регламенту.
4. DevOps восстанавливает сервис, QA выполняет smoke tests.
5. Оператор сверяет резервные заказы с постоянной базой по временным номерам и контактам; подтверждает отсутствие дублей.
6. PM закрывает инцидент после сверки и публикует отчёт.

Это организационный BCP, а не только техническое копирование базы. Реальное время восстановления должно подтверждаться испытаниями.
